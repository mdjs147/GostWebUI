# 连接测试说明

三类测试各自回答一个不同的问题,组合起来能把故障定位到具体环节。

## 1. 代理可达性(/api/test/proxy)
**问题**:配置的代理端口(如本机 SOCKS5 端口 3066)在监听吗?
**做法**:对 `proxyHost:proxyPort` 发起裸 TCP 连接,连上即算通。
**用途**:排查「代理软件未运行 / 端口填错 / 代理入站未启用」。

## 2. 端到端链路(/api/test/target)——最有价值
**问题**:经配置的 SOCKS5 代理,能真正连到目标吗?
**做法**:`Socks5Tester.TestThroughSocks5Async` 自己实现最小 SOCKS5:
1. 连代理端口;连不上 → 明确报「代理不可达,确认代理软件已运行且端口正在监听」。
2. 握手:发 `05 01 00`(VER=5, 1 种方法, 无认证),读 2 字节应答。
   - `VER != 5` → 该端口不是 SOCKS5(可能填成了 HTTP 端口)。
   - 第二字节 `0xFF` → 代理要求认证。
3. CONNECT:发 `05 01 00 03 <域名长度> <域名> <端口大端>`,请代理去连目标。
4. 读应答,看第 2 字节 `REP`:
   - `0x00` → **整条链路通**(本机 → SOCKS5 代理 → 代理上游 → 目标)。
   - 非 0 → 代理可达但到目标失败,`DescribeSocks5Reply` 给出中文原因(如 0x05 目标拒绝、0x04 主机不可达)。

**关键价值**:能区分「代理本身的问题」和「代理到目标的问题」,不用先起 gost 转发就能验证代理链路是否有效。

## 3. 本地监听(/api/test/listener)
**问题**:某条规则的 gost 转发起来了吗?本地监听端口(如 41011)在听吗?
**做法**:对 `127.0.0.1:port` 发起裸 TCP 连接。
**用途**:确认「启动」后 gost 确实监听了本地端口;也可用来查端口是否被别的进程占用。

## 典型排查流程
1. 先 `/test/target`:直接验证代理链路。失败且提示「代理不可达」→ 启动代理软件并检查配置的代理端口。
2. 链路通后点「启动」,再 `/test/listener`:确认本地端口起来了。
3. 本地程序连 `127.0.0.1:41011` 实测。

## 注意
- 全部是 **TCP / SOCKS5 CONNECT** 语义,不覆盖 UDP。
- 端到端测试成功只代表「能建立连接」,不代表目标应用层握手成功(如 TLS、私有协议)。作为「基础连接测试」足够。
- 超时默认 5000ms,可在请求体里用 `timeoutMs` 覆盖。
